# Архитектура и инженерные решения

## Команда в Telegram

1. Telegram отправляет обновление на HTTPS-обработчик Cloudflare. Worker проверяет заголовок секретного токена, тип чата и команду. Передаёт только поля, нужные обработчику.
2. Worker шифрует обновление AES‑256‑GCM. В параметры запуска GitHub попадает шифротекст, в том числе при вводе гостевого пароля.
3. GitHub Actions запускает Node.js-обработчик. Он расшифровывает обновление, проверяет личный чат и роль, затем рассчитывает отчёт или меняет доступ. Изменения доступа сохраняются в зашифрованном объекте в отдельной ветке `bot-access`. Запись привязана к версии объекта GitHub.
4. Telegram принимает форматированный отчёт. Меню ограничено ролью, а право на просмотр повторно проверяется перед выполнением команды. Смена общего пароля отзывает доступ всех гостей. После добровольного выхода гость может войти повторно по действующему паролю.

## Рыночные данные и расчёты

- **MOEX ISS** отдаёт публичные цены, предыдущие закрытия, свечи и купонный календарь. Владелец может получать более свежую цену последней сделки через Т‑Инвестиции. Гостей обслуживают публичные котировки ISS.
- **Т‑Инвестиции** через токен только для чтения могут вернуть актуальные позиции, среднюю цену, рублёвый остаток и дивидендные события. При сбое бот помечает использование сохранённого состава или конфигурации. Кэш прошлого успешного запуска связывается с конфигурацией и счётом.
- **Оценка облигаций.** Биржевая цена в процентах умножается на номинал и количество. Оценка бумаг без НКД. Текущая стоимость минус подтверждённая себестоимость даёт результат позиции.
- **Купоны.** Известные выплаты умножаются на количество бумаг. Годовой ориентир равен 12 суммам за следующий полный календарный месяц, когда для расчёта хватает данных. Это показатель купонного потока при сохранении допущений, без погашения номинала и налогов. Он отличается от доходности к погашению.
- **История и сигналы.** Для графика стоимости сохраняется до одной полной точки в день. Технические правила используют завершённые дневные свечи, среднюю цену покупки и доступные данные об отсечках. История котировок и индикаторы используются для условных сценариев, качество прогноза не оценивалось на бэктесте.

## Расписание и отказы

Отчёт владельцу запланирован каждые три часа в заданных окнах по Москве. Гостевая рассылка использует тот же последний запуск дня. Гости группируются по актуальному списку доступа. Доставка фиксируется по московской дате и хеш-маркерам чатов, чтобы обычный повтор запуска не дублировал уже отправленные сводки.

В ранней схеме команды и отчёты зависели от cron. По журналу GitHub удалось отличить успешную ручную доставку от отсутствующего автоматического запуска. Обработка команд переведена на webhook. Рассылки остались плановыми, а тайм-ауты и устаревшие котировки обрабатываются при формировании отчёта.

## Что важно при эксплуатации

| Решение | Компромисс |
|---|---|
| GitHub Actions для плановых запусков | Задания могут запаздывать и пропускаться. За пределами торгового окна отправка пропускается. Праздники и исключения биржи требуют сверки со статусами торгов. |
| Кеш для снимков, купонов и маркеров рассылки | Кеш может быть вытеснен. После сбоя между отправкой в Telegram и сохранением снимка возможен дубль. Для гарантии доставки нужен отдельный журнал с повторными попытками. |
| Зашифрованный маршрут команды через GitHub | GitHub принимает запрос на запуск раньше, чем обработчик ответит пользователю. Успешный webhook означает принятие запуска, а доставку отчёта проверяют по журналу. |
| Общий пароль для гостей | Подходит для небольшого закрытого списка. Гранулярные приглашения и ограничения попыток входа потребуют следующей итерации. |
| Деньги и позиции в приватной установке | Снимок портфеля в кеше GitHub содержит данные счёта. Демо-репозиторий для показа не следует использовать как рабочую установку. |
