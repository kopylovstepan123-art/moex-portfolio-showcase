# Архитектура и инженерные решения

Документ описывает актуальную рабочую установку. Публичный репозиторий содержит ранний демонстрационный срез для локального запуска и тестов.

## Команда в Telegram

1. Telegram отправляет обновление на HTTPS-обработчик Cloudflare. Worker проверяет заголовок секретного токена, тип чата и команду. Передаёт только поля, нужные обработчику, и ограничивает частоту команд по чату и по общему потоку.
2. Worker шифрует обновление AES‑256‑GCM. В параметры запуска GitHub попадает шифротекст, в том числе при вводе гостевого пароля.
3. GitHub Actions запускает Node.js-обработчик. Он расшифровывает обновление, проверяет личный чат и роль, затем рассчитывает отчёт или меняет доступ. Изменения доступа сохраняются в зашифрованном объекте в отдельной ветке `bot-access`. Запись привязана к версии объекта GitHub.
4. Telegram принимает форматированный отчёт. Меню ограничено ролью, а право на просмотр повторно проверяется перед выполнением команды. Смена общего пароля отзывает доступ всех гостей. После добровольного выхода гость может войти повторно по действующему паролю.

## Рыночные данные и расчёты

- **Т‑Инвестиции** возвращают состав, средние цены, рублёвый остаток и общую оценку. Бот также получает биржевые котировки, дневные свечи, номиналы, купоны и дивиденды. При сбое брокерского счёта бот помечает использование сохранённого состава или конфигурации.
- **MOEX ISS** даёт базовую цену для расчёта изменения за день и заполняет пропуски по котировкам, свечам и купонам. На проверенных бумагах дневные свечи совпали, а базовые цены закрытия у источников различались.
- **Оценка облигаций.** Сводка владельца отдаёт приоритет оценке из брокерского портфеля. При пересчёте биржевой котировки цена в процентах умножается на номинал и делится на 100.
- **Купоны.** Известные выплаты умножаются на количество бумаг. Годовой ориентир равен 12 суммам за следующий полный календарный месяц, когда для расчёта хватает данных. Это показатель купонного потока при сохранении допущений, без погашения номинала и налогов. Он отличается от доходности к погашению.
- **Сигналы.** Правила используют завершённые дневные свечи, среднюю цену покупки, индикаторы, доступные раскрытия и дивидендные отсечки. Сценарии условны. Точность сигналов на исторических данных пока не измерялась.

## Расписание и отказы

Отчёт владельцу запланирован каждые четыре часа в заданных окнах по Москве. Утренний запуск также отправляет сигналы. Гостевая рассылка использует последний запуск дня и актуальный список доступа. Доставка фиксируется по московской дате и хеш-маркерам чатов, чтобы обычный повтор запуска не дублировал уже отправленные сводки.

В ранней схеме команды и отчёты зависели от cron GitHub. Обработка команд переведена на webhook, а плановые рассылки запускает Cloudflare Cron Triggers. Исполнение остаётся в GitHub Actions.

## Что важно при эксплуатации

| Решение | Компромисс |
|---|---|
| GitHub Actions для плановых запусков | Задания могут запаздывать и пропускаться. За пределами торгового окна отправка пропускается. Праздники и исключения биржи требуют сверки со статусами торгов. |
| Кеш для снимков, купонов и маркеров рассылки | Кеш может быть вытеснен. После сбоя между отправкой в Telegram и сохранением снимка возможен дубль. Для гарантии доставки нужен отдельный журнал с повторными попытками. |
| Зашифрованный маршрут команды через GitHub | GitHub принимает запрос на запуск раньше, чем обработчик ответит пользователю. Успешный webhook означает принятие запуска, а доставку отчёта проверяют по журналу. |
| Общий пароль для гостей | Подходит для небольшого закрытого списка. Смена пароля отзывает доступ всех гостей. Ограничения Cloudflare приблизительные и применяются по точкам присутствия. |
| Деньги и позиции в приватной установке | Снимки и рыночный кеш шифруются перед сохранением в GitHub Actions. Права на доступ к реальному счёту настраиваются в приватной установке. |
